## Что должно заработать

Весь сценарий PDF записан данными: каталог текстов (каждый вопрос, подсказка, вариант, поле «→ поле», информационный блок, кнопки навигации, тексты ошибок, сводки и краткие заголовки для «Исправить») и граф узлов со всеми ветками и переходами. Движок (тикет 03) будет только исполнять эти данные. Тексты — дословно из PDF, кроме двух смягчённых фраз о конфиденциальности (спецификация, «Конфиденциальность» и «Заявки»).

## Из брифа, дословно

> «PDF — спецификация поведения бота … Не пропускай ветки или варианты ответов ради сокращения работы.»
> «Все ветки нового сайта: товары, услуги, товары и услуги, ручной вариант; все указанные в PDF вопросы и переходы.»
> «Все ветки доработки и продвижения, включая условные вопросы.»
> «Проверь, что формулировки о конфиденциальности не обещают того, чего технически нельзя гарантировать.»
> Дополнения: ручной вариант — «описание → структура сайта → разделы → дизайн → пример сайта/ТЗ → контакты»; продвижение «Никогда»/«Затрудняюсь» — «сразу к финальному блоку».

## Разделы спецификации

«Сценарий — граф диалога» целиком (0–6), «Источник текстов», «Исключающие варианты», «Проверка ввода» (тексты ошибок), «Доп. функция» (тексты сводки), «Заявки и доставка» (тексты для владельца), «Конфиденциальность». `interfaces.md` — `texts`, `scenario`. Источник строк: `.autopilot/2026-10-20-telegram-leads-bot--wip/scenario-raw.txt` и `scenario.pdf` (эмодзи подобрать по смыслу — в текстовом слое они испорчены).

## Критерии приёмки

- [ ] `TEXTS` содержит каждый вопрос, подсказку и вариант ответа PDF стр. 3–28 дословно (тест сверяет список ожидаемых строк, выписанных из PDF, с дефолтами — без учёта эмодзи)
- [ ] Каждый текст отнесён к группе панели (`GROUPS`) и имеет русскую подпись; информационные блоки (`kind="info"`) — отдельная группа
- [ ] `TextStore.get` отдаёт правку из базы, иначе дефолт; `{name}` подставляется; неизвестный ключ — `KeyError`
- [ ] `NODES`/`BRANCHES` описывают ветки goods, services, both, other, promo, redesign, final в порядке спецификации; хаб имеет варианты `goods` («Услуги и товары») и `services` («Услуги» без «Товары (если есть каталог)»); у «Правовой информации» нет «Добавить свой вариант»
- [ ] Каждый вариант с полем из PDF имеет `InputSpec` с нужным типом (text / url / urls / file); исключающие варианты помечены `exclusive`; «Никогда не продвигали» и «Затрудняюсь ответить» — `final_jump`
- [ ] `next_node` ведёт pr_current → pr_helpers при любом из первых пяти вариантов и → FINAL при `final_jump`
- [ ] Граф проверен тестом: каждый `text_key`/`question_key`/`title_key` есть в `TEXTS`, каждый `next` указывает на существующий узел, из каждого узла веток достижим FINAL, каждый callback-идентификатор узла и варианта укладывается в лимит 64 байт формата `interfaces.md`
- [ ] Текст блока конфиденциальности и финальная фраза — смягчённые формулировки из спецификации; опечатка «еды и кулинарии» у спорта исправлена
