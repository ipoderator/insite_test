## 2. Платформа и технология

**Собственное решение на Python**, без конструкторов и бот-платформ:

- Telegram Bot API через webhook (`POST /tg/webhook`); чужие запросы без секретного заголовка `X-Telegram-Bot-Api-Secret-Token` получают 403;
- Flask (WSGI) — webhook, веб-панель, демо-страница политики; `requests` — тонкий клиент Bot API; SQLite — заявки, состояния диалогов, тексты, настройки, примеры работ (данные переживают перезапуск);
- сценарий PDF описан как данные (54 экрана, 427 текстов), один движок проходит все ветки; тексты по умолчанию — в коде, правки заказчика — в базе;
- хостинг демо — **PythonAnywhere**, бесплатный тариф Beginner: без банковской карты, HTTPS на `ipoderator.pythonanywhere.com`, постоянный диск, `api.telegram.org` в белом списке исходящих соединений. Flask и requests там предустановлены.
- Запасной вариант (Render) не понадобился: PythonAnywhere подошёл. Единственная неожиданность — API хостинга принимает версию Python только при создании приложения, а не при изменении; скрипт деплоя поправлен (`docs/adr/0006`). Он описан в [DEPLOY.md](DEPLOY.md). На бесплатном Render файловая система не постоянная, поэтому для SQLite нужен платный диск или переход на Postgres (меняется один модуль хранения).

## 3. Дополнительная функция: сводка заявки с исправлением ответов

**Что сделано.** Перед отправкой бот показывает «📋 Проверьте заявку»: тип заявки, все ответы по порядку вопросов (кратко: «Текущее продвижение: …»), имя, телефон, мессенджеры, удобное время, отметку о файлах ТЗ. Кнопки: **✅ Отправить заявку** и **✏️ Исправить**. «Исправить» открывает список вопросов этой анкеты. Клиент выбирает любой, видит его с прежними отметками, отвечает — и возвращается к сводке. Если исправлен вопрос, меняющий ветку (тип сайта или «Сейчас вы уже что-то продвигаете?»), бот проводит по новым вопросам, сохраняя уже данные ответы, и снова показывает сводку.

**Какую задачу решает.** Анкета длинная: в ветке «Товары и услуги» больше 15 вопросов. Без сводки клиент, ошибившийся в начале, либо отправляет неверную заявку, либо бросает анкету и начинает заново. Со сводкой:

- клиент видит, что именно уйдёт специалисту, и исправляет ошибку за два нажатия;
- владелец получает выверенную клиентом заявку — меньше уточняющих звонков;
- меньше брошенных анкет: исправление не требует проходить всё заново.

Краткие заголовки в сводке заказчик меняет в панели, как и любые тексты. Функция покрыта автотестами (сводка, исправление, смена ветки, повторная отправка).

## 4. Администрирование

Защищённая веб-панель на русском — <https://ipoderator.pythonanywhere.com/admin>, работает с телефона. Подробно — [ADMIN_GUIDE.md](ADMIN_GUIDE.md).

Заказчик сам, без программиста, меняет:

- **тексты** — все сообщения, вопросы, подсказки и кнопки бота, сгруппированы по экранам, с поиском, отметкой изменённых и «Вернуть по умолчанию»;
- **информационные блоки** — конфиденциальность, приветствие, вступления, «Остался последний шаг», финальное сообщение, «Связаться с нами» и др.;
- **контакты и ссылку на политику конфиденциальности**; демо-текст страницы политики;
- **примеры работ** — сферы и примеры (ссылка, описание, порядок, пометка «демо», скрыть);
- **получателя заявок** — привязка личного чата или группы командой `/owner КОД`, тестовое сообщение;
- **заявки** — список с фильтрами, карточка с ответами и файлами ТЗ, «Обработана», повторная отправка владельцу.

Изменения применяются сразу, со следующего сообщения клиента. Защита: пароль (сравнение за постоянное время), блокировка после 5 неверных попыток на 15 минут, cookie HttpOnly / SameSite / Secure, CSRF-токены во всех формах, сессия 12 часов.

Без разработчика нельзя менять структуру анкеты (новые вопросы, порядок, переходы) и пароль панели — это изменения кода и настроек хостинга.

**152-ФЗ.** Бот собирает персональные данные: имя, телефон, Telegram-профиль. По ч. 5 ст. 18 Федерального закона № 152-ФЗ при сборе персональных данных граждан РФ их запись, хранение и обработка должны вестись в базах данных на территории РФ. Поэтому для продакшна база должна лежать на сервере в России (вариант B); PythonAnywhere подходит только для демо. Оператору персональных данных также нужны опубликованная политика обработки ПДн (в панели есть место для ссылки), согласие клиента на обработку и уведомление Роскомнадзора. Сообщения клиента в любом случае проходят через серверы Telegram — это стоит отразить в политике. Для финального решения нужна консультация юриста; этот раздел — не юридическое заключение.

## 8. Риски, заметки, правки текстов сценария

**Риски по срокам.** Код, тесты и документация готовы в первый день. Риск — шаги, которые требуют аккаунта и секретов владельца (бот в BotFather, аккаунт и API-токен PythonAnywhere): без них деплой невозможен. Задержек не было: владелец сделал эти шаги, пока шла разработка. Дополнительные дни не потребовались.

**Правки текстов PDF.** Все тексты сценария сохранены, исправлено только перечисленное ниже; заказчик может вернуть любую формулировку в панели.

- Опечатка: у сферы «Спорт / отдых / тренеры» в PDF повторена фраза «по тематике еды и кулинарии» → «по тематике спорта и отдыха».
- Опечатка: «какое наполнение и в каком **формат** есть» → «в каком **формате** есть».
- Блок конфиденциальности: PDF обещает «Мы не передаём ваши данные третьим лицам», но технически это не гарантируется (сообщения идут через Telegram, база — у хостинг-провайдера). Текст по умолчанию: «Ваши ответы нужны только для подготовки предложения по вашему запросу. Мы не продаём и не передаём их для рекламы. Сообщения проходят через Telegram, а заявка хранится на сервере, где работает бот. Подробнее — Политика конфиденциальности».
- Финальное сообщение: «Вся ваша информация передана напрямую специалисту — без посредников и задержек» → «Ваша заявка передана специалисту» (посредники — Telegram и хостинг — есть).
- Подсказки ссылок в продвижении: в PDF везде «Введите ссылку» → уточнено, на что: «Введите ссылку на профиль в 2ГИС», «… на Яндекс Бизнес», «… на Яндекс Карты», «… на Яндекс Услуги».
- Значок «✅» в начале семи вариантов ответа («✅ Да, есть», «✅ Есть логотип…», «✅ Есть все тексты и материалы» и др.) заменён на 👍 / 📦 / 🔑: бот отмечает выбранный вариант знаком «✅», и с собственным «✅» вариант выглядел выбранным, а выбранный показывался как «✅ ✅ …». Слова вариантов не изменены.

**Демо-данные.** Ссылок на примеры работ в PDF нет («все ссылки на скрины сайтов отправлю позже»). Примеры заведены с названиями из PDF, пометкой «(демо)» и без ссылок. Политика конфиденциальности — демо-страница с явной пометкой. Реальные данные не придумывались; всё меняется в панели.

**Конфиденциальность в демо.** Токен бота, пароль панели и ключи хранятся только в `.env` (вне git) — локально и на хостинге. Скрипты деплоя и проверки не печатают их ни в каком режиме.

**Найдено проверками и оставлено как есть** (не мешает сдаче, при желании — следующая итерация):

- Фраза «Ваша заявка передана специалисту» показывается и тогда, когда Telegram не доставил заявку владельцу. Заявка при этом сохранена в панели с пометкой «не доставлена», и её можно отправить повторно. Формулировку можно поправить в панели.
- Блокировка входа в панель снимается через 15 минут после первой из пяти неудачных попыток, а не после последней. Темп подбора пароля при этом всё равно не больше 5 попыток за 15 минут.
- Если на шаге телефона отправить /menu, под полем ввода может остаться кнопка «Отправить мой номер». Её нажатие безвредно.
- Запрос кнопки, подделанный вне клиента Telegram, может пропустить шаг телефона. Telegram-профиль клиента в заявке всё равно есть.
- Локальный симулятор считает строку из одних цифр номером кнопки, поэтому телефон там вводится с «+7».
- Скрипт деплоя при битом ответе PythonAnywhere показывает трассировку вместо понятной ошибки. Для переезда на Render секрет webhook нужно перенести из серверного `.env` в локальный (описано в DEPLOY.md).

**Безопасность демо.** Токен бота, API-токен PythonAnywhere и пароль панели при настройке побывали в переписке с ИИ-ассистентом: владелец вписал их в шаблон `.env.example`, открытый в редакторе. В git они не попали. Рекомендуется перевыпустить токен бота (@BotFather → `/revoke`) и API-токен PythonAnywhere, сменить пароль панели, обновить `.env` и перезапустить деплой.
