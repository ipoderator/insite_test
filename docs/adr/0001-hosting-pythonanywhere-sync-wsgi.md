## Контекст

Тестовое задание требует бесплатное демо, по возможности без банковской карты, на своём коде без бот-платформ, через webhook. Язык задан брифом — Python.

## Решение

Бот и панель — одно WSGI-приложение на Flask с синхронными вызовами Bot API через `requests`. Демо живёт на PythonAnywhere. Рантайм-зависимостей две: `flask` и `requests`; всё остальное — стандартная библиотека, даже загрузчик `.env` свой.

## Почему

- Конструкторы и готовые бот-платформы отвергнуты брифом: нужно «собственное программное решение».
- Render (веб-сервис с постоянным диском или Postgres) оставлен запасным вариантом, а не первым выбором: PythonAnywhere не требует карту, даёт HTTPS-домен, WSGI и постоянный диск, а Flask и `requests` там уже установлены, так что virtualenv не нужен.
- `python-dotenv` и любые другие библиотеки отвергнуты: каждая зависимость — лишняя точка отказа при деплое на чужой хост.
- Свой тонкий клиент вместо готовой библиотеки Telegram: `requests` сам берёт прокси PythonAnywhere из окружения.

## Последствия

- Код обязан работать на Flask 2.2: на хостинге может стоять версия старее локальной, поэтому нельзя использовать более новые API Flask.
- Стек синхронный и привязан к модели WSGI: обработка апдейта блокирует воркер, пока идут запросы к Telegram. Бесплатный тариф даёт узкое место по нагрузке; для продакшна понадобится другой хостинг.
- Бесплатный тариф ограничивает исходящие соединения белым списком. Сейчас `api.telegram.org` в нём есть, но это внешнее условие, которое хостинг может изменить.
- Переход на Render потребует нового деплой-скрипта: текущий написан под API PythonAnywhere.
- Свой клиент Bot API и свой загрузчик `.env` — это код, который теперь сопровождаем мы сами.
