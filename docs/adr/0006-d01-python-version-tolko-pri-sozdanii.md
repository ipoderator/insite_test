## Контекст

План предполагал, что деплой-скрипт задаёт версию Python тем же запросом PATCH, которым обновляет остальные настройки веб-приложения на PythonAnywhere, и тем самым выравнивает уже существующее приложение.

## Решение

Версия Python указывается только при создании веб-приложения; запрос PATCH версию не передаёт. Значение по умолчанию — `python311`, его можно переопределить флагом скрипта.

## Почему

Реальный деплой показал: API PythonAnywhere v0 отвечает на PATCH с этой версией ошибкой HTTP 400 («"python311" is not a valid choice»). Проверять, какие значения принимает PATCH, не стали: ошибка приходит на допустимую при создании строку, значит поле при изменении не поддерживается. Оставить версию в PATCH отвергнуто как заведомо ломающее каждый повторный деплой.

## Последствия

- Скрипт не умеет менять версию Python у уже созданного приложения; такой деплой тихо оставляет старую версию.
- Возможный способ смены версии через API или панель хостинга не проверялся; пока он не проверен, путь смены версии — пересоздание приложения или ручная правка на хостинге.
- Версия, заданная при создании, и версия, на которую рассчитан код (3.10+), должны совпасть без проверки: скрипт не сверяет их после создания.
- Если API изменится, поведение придётся проверять заново: решение опирается на наблюдение, а не на документацию.
