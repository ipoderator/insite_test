# Спецификация: Telegram-бот заявок на сайты и продвижение

## Задача

Веб-студии нужен чат-бот, который сам проводит клиента по анкете — новый сайт, доработка, продвижение — и отдаёт владельцу полную заявку, не теряя ни одного ответа. Сценарий задан в PDF заказчика (`scenario.pdf`, 28 стр.). Заказчик хочет сам, без программиста, менять тексты, контакты, ссылку на политику, информационные блоки и примеры работ. Это тестовое задание: нужны работающее демо на бесплатном хостинге и отчёт (ссылки, инструкции, время, расходы, оценка стоимости).

## Решение

- Telegram-бот на Python, свой код: webhook, собственный конечный автомат, без конструкторов и бот-платформ.
- Все экраны, вопросы, варианты, условные поля и переходы PDF. Одиночный и множественный выбор с отметками ✅. Ручной ввод с проверкой, ссылки, загрузка ТЗ, «Назад» и «Готово» на каждом шаге. Ответы сохраняются: вернулся назад — отметки на месте.
- Перед отправкой клиент видит сводку всех ответов и может исправить любой (доп. функция, R79).
- Заявка сохраняется в базе и уходит владельцу в Telegram — в личный чат или рабочую группу — вместе с файлом ТЗ. Все заявки также видны в веб-панели.
- Защищённая веб-панель на русском: заявки, тексты (все сообщения, вопросы, кнопки, информационные блоки), контакты и ссылки, примеры работ, получатель заявок, демо-страница политики. Изменения видны в боте со следующего сообщения.
- Хостинг — PythonAnywhere (бесплатно, без карты, HTTPS, постоянный диск, SQLite).

## Решения по реализации

| Решение | Почему |
|---|---|
| Python 3.10+, Flask (WSGI), `requests`, `sqlite3` из стандартной библиотеки. Других зависимостей в рантайме нет | R06. PythonAnywhere — WSGI-хостинг, Flask и requests там уже установлены, virtualenv не нужен. Меньше зависимостей — меньше точек отказа при деплое |
| Свой тонкий клиент Bot API на `requests` | R07: «собственное решение». `requests` сам берёт прокси PythonAnywhere из окружения |
| Webhook `POST /tg/webhook`, проверка заголовка `X-Telegram-Bot-Api-Secret-Token` | R08. Чужие POST-запросы отклоняются ответом 403 |
| Одна SQLite-база на диске хостинга: настройки, тексты, сессии диалогов, заявки, примеры работ, обработанные `update_id`, попытки входа | R09: данные переживают перезапуск. Весь доступ к базе идёт через один модуль `storage`, поэтому переход на Postgres меняет только его |
| Сценарий описан декларативно, как данные (узлы и переходы), движок один на все ветки | R02: каждый вариант PDF — строка данных, а не ветка `if`; тесты проходят граф целиком |
| Тексты: значения по умолчанию в коде, правки из панели в таблице `texts`. Бот читает базу на каждом апдейте | R73, R78: правка применяется без перезапуска. Кнопка «Вернуть по умолчанию» |
| Тексты из панели — простой текст. Бот экранирует всё, что отправляет (`parse_mode=HTML`), и сам выделяет заголовок вопроса жирным. Подстановка — только `{name}` в финальном сообщении, через `str.replace` | Админ не сломает отправку неверной разметкой, а клиент не внедрит HTML |
| Время хранится в UTC, показывается по Europe/Moscow | Заявки читают в РФ |
| Секреты только в переменных окружения (`.env` на хостинге и локально, в git не попадает) | R83 |

### Конфигурация (переменные окружения)

`TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET`, `ADMIN_PASSWORD` (не короче 10 символов, иначе приложение не стартует и пишет понятную ошибку в лог), `SECRET_KEY` (сессии Flask), `DATABASE_PATH` (по умолчанию `data/bot.sqlite3`), `PUBLIC_BASE_URL` (для ссылки на демо-политику). Для деплоя (только локально): `PA_USERNAME`, `PA_API_TOKEN`, `PA_HOST` (`www.pythonanywhere.com` или `eu.pythonanywhere.com`).

## Сценарий — граф диалога

**Источник текстов.** Все тексты вопросов, подсказок, вариантов, информационных блоков и названия примеров работ берутся дословно из PDF. Текстовый слой — `.autopilot/2026-10-20-telegram-leads-bot--wip/scenario-raw.txt`, эмодзи в нём испорчены; оригинал — `scenario.pdf`. Таблицы ниже называют узлы и логику. Где написано «N вариантов PDF», варианты переносятся из PDF полностью, в том порядке, без сокращений: design (стр. 8), sphere (стр. 8–9), structure, content (стр. 9), popup с подсказкой «Они могут облегчить восприятие длинных страниц, либо открываться при клике «Подробнее».» (стр. 10), flows (стр. 18), pr_types (стр. 19), pr_support «Вас интересует разовая настройка или сопровождение?» (стр. 20), pr_geo «География продвижения:», pr_goals «Какие цели у рекламы?» (стр. 20), rd_what, rd_rebuild, rd_access (стр. 21–23), пункты каждой категории хаба (стр. 6–7, 11–12, 16–17), сайты и фразы «по … тематике» в карточках примеров (стр. 24–27). Финальное сообщение — весь текст стр. 23–24, включая «Если появятся дополнительные вопросы — смело пишите сюда, бот всегда на связи.»; меняется только фраза «без посредников», см. «Заявки».

**Исключающие варианты** (R65.1, решение по ремеслу): вариант, который по смыслу отрицает остальные («Нет» в вариациях, «Пока нет сайта и других каналов», «Не знаю, нужна рекомендация», «Нет, никогда не обращались», «Нет, пока не продвигаем», «Никогда не продвигали», «Затрудняюсь ответить»), снимает прочие отметки, и наоборот. Иначе заявка получит противоречие вида «Нет + Цвет».

Обозначения: **S** — один выбор, **M** — множественный выбор (отметки ✅, кнопка «✅ Готово»), **T** — ввод текста, **U** — ввод ссылки, **F** — загрузка файла. «→ поле» — после выбора бот просит ввести текст. У каждого вопроса, кроме экрана конфиденциальности, есть «⬅️ Назад», даже там, где PDF кнопку не показывает (например, «Что будет приоритетом?»): так требует R68. Тексты вопросов, подсказок и кнопок — дословно из PDF. Эмодзи PDF при извлечении потерялись, поэтому подобраны по смыслу; их можно править в панели.

## Механика диалога

- **Состояние** (R09, R69): на каждый чат одна строка в базе — текущий узел, стек пройденных узлов (путь), ответы по ключу `ветка/узел`, режим исправления. Пишется в базу после каждого апдейта: перезапуск сервиса продолжает диалог с того же места.
- **Назад** (R68): из стека выбирается предыдущий узел. Ответ текущего узла не стирается: при возврате вперёд отметки на месте. Назад из первого вопроса ветки → в меню (из ветки нового сайта — в ns_what). Назад из поля «→ поле» — к вопросу, который его открыл.
- **Сообщения**: каждый новый вопрос — новое сообщение. Переключение отметок M редактирует то же сообщение. Отвеченный вопрос редактируется: кнопки убираются, под текстом появляется «— Ваш ответ: …», и в чате остаётся читаемая история.
- **Устаревшие кнопки** (R97i): в callback-data зашит узел. Нажатие кнопки не текущего узла → всплывающее «Эта кнопка уже неактивна» + текущий вопрос заново. Текст, присланный там, где ждут кнопку, → «Пожалуйста, выберите вариант кнопкой ниже» + вопрос заново.
- **Повтор апдейтов**: уже обработанный `update_id` пропускается, повторная отправка webhook не дублирует заявку. Повторное нажатие «Отправить» после отправки — «Заявка уже отправлена».
- **/start посреди анкеты** (A02 → R97i): «У вас есть незаконченная анкета. Продолжить или начать заново?» «Начать заново» очищает ответы. `/menu` — меню без потери ответов.
- **Черновик**: ответы живут в сессии до отправки. Повторный вход в ту же ветку из меню показывает прежние отметки. После отправки ответы очищаются.

## Проверка ввода (R70)

| Ввод | Правило | Сообщение об ошибке (по умолчанию, правится в панели) |
|---|---|---|
| Имя | 2–60 символов, буквы, пробел, дефис, апостроф; без ссылок и цифр | «Похоже, это не имя. Напишите, как к вам обращаться — например, Анна.» |
| Телефон | после очистки от пробелов, скобок и дефисов: `+` и 10–15 цифр; 8XXXXXXXXXX и 9XXXXXXXXX приводятся к +7. Принимается и контакт Telegram | «Не получилось распознать номер. Пример: +7 999 123-45-67» |
| Ссылка | `http(s)://` или домен вида `name.tld[/путь]`; без схемы дописывается `https://`; пробелов внутри нет; ≤ 500 символов. Для соцсетей — одна или несколько через пробел или с новой строки | «Это не похоже на ссылку. Пример: https://example.ru или example.ru» |
| Свободный текст | 2–1000 символов после обрезки пробелов | «Слишком коротко / слишком длинно (максимум 1000 символов)» |
| Файл ТЗ | документ или фото; расширения pdf, doc, docx, rtf, odt, txt, xls, xlsx, ppt, pptx, png, jpg, jpeg, zip; ≤ 20 МБ (лимит Bot API); можно несколько файлов, затем «Готово» | «Этот формат не подходит…» / «Файл больше 20 МБ — пришлите ссылку на облако через «Назад» → «Иное»» |
| Пустой M | «Готово» без отметок | всплывающее «Выберите хотя бы один вариант» |
| Стикер, голосовое, фото не к месту | — | «Я понимаю здесь только текст / кнопки» + вопрос заново |

## Доп. функция — сводка и исправление (R79)

1. После последнего вопроса финального блока бот присылает «Проверьте заявку»: тип заявки, все ответы по пути в порядке вопросов («Краткий заголовок: ответ»), имя, телефон, мессенджеры, время, отметка о файлах ТЗ. Длинная сводка делится на сообщения до 4096 символов.
2. «✏️ Исправить» → список вопросов пути кнопками (краткие заголовки, правятся в панели) + «⬅️ К сводке».
3. Исправление вопроса показывает его с прежними отметками. После ответа (и его полей) бот возвращается к сводке. Если исправлен вопрос, который меняет ветку (ns_what, pr_current), путь после него перестраивается и бот проходит новые вопросы — прежние ответы стоят отметками — и снова выходит на сводку.
4. «✅ Отправить заявку» → сохранение, доставка, финальное сообщение.

## Заявки и доставка владельцу (R59, R95i, R96i)

- Заявка (тип: новый сайт / доработка / продвижение / запрос примеров) сохраняется в базе **до** попытки доставки.
- Получатель — чат владельца, привязанный командой `/owner <КОД>`. Код показан в панели, после привязки меняется. Работает в личке и в группе (бот добавлен в группу). В панели: текущий получатель, «Отправить тестовое сообщение», «Отвязать», «Сменить код».
- Владельцу приходит полный текст заявки: номер, дата по Москве, тип, Telegram-профиль клиента (@username / ссылка tg://user?id), все ответы, контакты; файлы ТЗ — отдельными сообщениями `sendDocument`/`sendPhoto` по `file_id`.
- Получатель не задан или Telegram вернул ошибку → заявка помечается «не доставлена» с причиной. Клиент всё равно получает благодарность, заявка видна в панели. В панели кнопка «Отправить повторно».
- Финальная фраза PDF «Вся ваша информация передана напрямую специалисту — без посредников и задержек» по умолчанию смягчена: «Ваша заявка передана специалисту» (R11).

## Веб-панель (R72–R78, R88)

Адрес `/admin`, интерфейс на русском, вёрстка адаптивная (работает с телефона), без внешних CDN.

- **Вход**: пароль из `ADMIN_PASSWORD` (сравнение за постоянное время). После 5 неверных попыток за 15 минут с одного IP вход блокируется на 15 минут. Сессия: cookie HttpOnly, SameSite=Lax, Secure на HTTPS; срок 12 часов; «Выйти». Все POST-формы с CSRF-токеном.
- **Заявки**: таблица (№, дата, тип, имя, телефон, доставлена ли, статус), фильтр по типу и статусу; карточка с полной сводкой, файлы ТЗ (скачивание через сервер с Telegram), «Отметить обработанной», «Отправить владельцу повторно». Пустой список → «Заявок пока нет — пройдите анкету в боте».
- **Тексты**: все тексты бота, сгруппированные по экранам (Вход и меню, Новый сайт, Продвижение, Доработка, Контакты клиента, Примеры, Связаться, Сводка, Ошибки ввода, Информационные блоки). У каждого текста — подпись, поле, значение по умолчанию и «Вернуть по умолчанию». Изменённые помечены. Поиск по тексту. Проверки: не пусто; ≤ 3500 символов для сообщений, ≤ 60 для кнопок. Сохранение → «Сохранено, бот уже использует новый текст».
- **Информационные блоки** — отдельный раздел (тот же механизм текстов): блок конфиденциальности, приветствие меню, вступление продвижения, примечание к примерам, «Остался последний шаг», финальное сообщение, текст «Связаться с нами», комментарий о продвижении в доработке.
- **Контакты и ссылки**: Telegram, телефон, email, ссылка на политику конфиденциальности (проверка URL). Пустое поле не показывается в боте.
- **Примеры работ**: сферы (название кнопки, название тематики для фразы «по … тематике», порядок, вкл/выкл) и примеры внутри (название, ссылка, описание, флаг «демо», порядок; добавить, изменить, удалить с подтверждением). Демо-примеры видны в боте с пометкой «(демо)».
- **Политика (демо)**: текст страницы `/privacy`, которую по умолчанию открывает ссылка из блока конфиденциальности. На странице крупная пометка «ДЕМОНСТРАЦИОННЫЙ ТЕКСТ — замените на реальную политику».
- **Получатель заявок**: см. выше.
- **Инструкция**: короткая страница «Как пользоваться панелью».

## Конфиденциальность (R11, R12)

Текст PDF обещает «Мы не передаём ваши данные третьим лицам». Технически это не гарантируется: сообщения проходят через серверы Telegram, а база лежит у хостинг-провайдера. Формулировка по умолчанию: «Ваши ответы нужны только для подготовки предложения по вашему запросу. Мы не продаём и не передаём их для рекламы. Сообщения проходят через Telegram, а заявка хранится на сервере, где работает бот. Подробнее — Политика конфиденциальности». Заказчик меняет её в панели. В отчёте — абзац о 152-ФЗ: для продакшна база с персональными данными граждан РФ должна храниться в РФ.

Демо-данные (R12): ссылки примеров не заданы (в PDF: «все ссылки на скрины сайтов отправлю позже»). Записи примеров — названия из PDF с флагом «демо» и без ссылок. Политика — демо-страница с явной пометкой. Реальные адреса не придумываются.

## Хостинг и деплой (R80–R83)

- **PythonAnywhere** (ответ брифинга): бесплатный аккаунт без карты, домен `<user>.pythonanywhere.com` с HTTPS, Flask через WSGI, постоянный диск. `api.telegram.org` есть в белом списке исходящих соединений бесплатного тарифа.
- `scripts/deploy_pythonanywhere.py` читает локальный `.env` (секреты не печатает) и через API PythonAnywhere:
  1. загружает код и серверный `.env`;
  2. создаёт веб-приложение, если его нет;
  3. пишет WSGI-файл, включает force HTTPS;
  4. перезапускает приложение;
  5. вызывает `setWebhook` с `secret_token` и `setMyCommands`;
  6. проверяет `/health` и `getWebhookInfo`.
- Пользователь делает только своё: создаёт бота в @BotFather, аккаунт PythonAnywhere и API-токен, вписывает значения в локальный `.env` по `.env.example`. Точная инструкция — в `docs/DEPLOY.md`.
- Проверка на хостинге (R81): `scripts/e2e_hosted.py` шлёт на боевой webhook подписанные апдейты, проходит полную анкету и сверяет через панель, что заявка сохранилась. Тестовые апдейты идут от имени чата владельца, только с согласия пользователя, и ответы бота придут ему в Telegram. Тот же скрипт меняет текст через панель и проверяет, что бот ответил новым текстом. Плюс короткий ручной прогон пользователем по чек-листу.
- Запасной вариант (R82), если PythonAnywhere не подойдёт: Render (веб-сервис) + постоянный диск или Postgres. Решение фиксируется строкой D## и в отчёте.

## Проверки (R84)

- `pytest`: модульные тесты валидаторов и хранилища; сценарные тесты через симулятор чата (фейковый Telegram-клиент, нажатия по подписи кнопки). Покрыт каждый узел графа и каждый вариант с полем: ветки G, S, B, M; продвижение с условием и исключающими вариантами; доработка; финал; сводка и исправление (включая смену ветки); примеры и заказ из них; контакты; Назад с сохранением отметок; устаревшие кнопки; повтор апдейта; перезапуск (новый экземпляр движка на той же базе продолжает диалог); доставка владельцу и ошибка доставки.
- Тесты панели через Flask test client: вход и блокировка, CSRF, правка текста меняет ответ бота, контакты, примеры (CRUD), привязка получателя, просмотр заявки. Webhook: неверный секрет → 403.
- Отдельный тест сверяет, что все тексты вопросов и вариантов из PDF есть в значениях по умолчанию.
- Ручная проверка на хостинге — по чек-листу в `docs/CHECKLIST.md`.
