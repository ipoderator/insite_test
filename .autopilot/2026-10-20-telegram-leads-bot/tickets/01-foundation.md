## Что должно заработать

Проект поднимается локально и на WSGI-хостинге: `wsgi.py` отдаёт Flask-приложение с `/health` и защищённым `/tg/webhook`, который передаёт апдейт в движок (движок пока заглушка — пишет апдейт в лог). Есть постоянное хранилище SQLite со всеми таблицами из `interfaces.md` и начальными данными из PDF, свой клиент Bot API, чистые функции проверки ввода и фейковый Telegram для тестов.

## Разделы спецификации

«Решения по реализации», «Конфигурация», «Проверка ввода», «Заявки и доставка владельцу» (только хранение). `interfaces.md` — разделы `config`, `storage`, `telegram`, `validators`, `web` (каркас), `wsgi`, «Швы для тестов» (FakeTelegram). Начальные данные для `seed_defaults` — PDF стр. 24–28 (`scenario-raw.txt`): 7 сфер примеров с названиями кнопок и тематиками (у спорта — «спорта и отдыха», не «еды и кулинарии»), все названия сайтов из PDF как демо-примеры без ссылок (`is_demo=1`, `url` пустой), контакты из стр. 28 (`contact_telegram=@site_it`, `contact_phone=+7 999 155-10-43`, `contact_email=site-it@mail.ru`), `privacy_url` пустой (значит — демо-страница `/privacy`), случайный `owner_bind_code`.

## Критерии приёмки

- [ ] `requirements.txt` содержит только flask и requests; `requirements-dev.txt` добавляет pytest; `.env.example` перечисляет все переменные из спецификации с пустыми значениями и комментариями на русском
- [ ] `Config.from_env` бросает понятный `ConfigError`, если переменной нет или пароль короче 10 символов; `load_dotenv` не перезаписывает заданные переменные
- [ ] `Storage` создаёт схему идемпотентно, переживает переоткрытие файла (данные на месте после нового `Storage(path)`), `seed_defaults` повторно не дублирует и не перетирает правки
- [ ] Все методы `Storage` из `interfaces.md` есть и покрыты тестами (настройки, тексты, сессии, идемпотентность апдейтов, заявки с доставкой и статусом, сферы и примеры CRUD, попытки входа)
- [ ] Валидаторы: имя, телефон (8…/+7…/9… → +7XXXXXXXXXX, международные 10–15 цифр), ссылка (с/без схемы, отказ на пробелы и мусор), несколько ссылок, свободный текст, файл (расширения и 20 МБ) — с ключами ошибок `err.*`
- [ ] `TelegramClient` формирует правильные запросы к Bot API (проверено подменой `requests.Session`), не пишет токен в логи, глотает «message is not modified», остальные ошибки — `TelegramError`
- [ ] `POST /tg/webhook` без верного заголовка `X-Telegram-Bot-Api-Secret-Token` → 403; с верным → 200 и апдейт передан обработчику; ошибка обработчика всё равно даёт 200; `GET /health` → `{"ok": true}`
- [ ] `tests/fakes.py::FakeTelegram` реализует все методы клиента и записывает вызовы
- [ ] `.venv/bin/python -m pytest -q` зелёный
